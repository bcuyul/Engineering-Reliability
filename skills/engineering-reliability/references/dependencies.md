# Dependencies / Dependencias

Reuse first. Compare native features, existing components and maintained OSS. For each candidate record upstream URL, exact release and date, license obligations, runtime/platform compatibility, support/EOL, known advisories, transitive dependencies, provenance and maintenance. Verify against official releases and advisory databases; lack of a known CVE is not proof of safety. Avoid prereleases by default. Routine updates may use a configurable observation period (e.g. seven days); urgent security fixes may require acceleration. Test major upgrades in isolation. Respect the existing package manager and lockfile. Use SBOM and scanners when useful, not by default. Record rollback and uncertainty.

Reutiliza primero. Compara funciones nativas, componentes existentes y OSS mantenido. Registra URL oficial, versión y fecha exactas, obligaciones de licencia, compatibilidad, soporte, avisos, dependencias transitivas, procedencia y mantenimiento. Verifica publicaciones oficiales y bases de vulnerabilidades; ausencia de CVE no demuestra seguridad. Evita versiones preliminares por defecto. Actualizaciones rutinarias pueden usar ventana configurable (p. ej. siete días); parches urgentes pueden acelerarse. Prueba cambios mayores aislados. Respeta gestor y lockfile. Usa SBOM y escáneres si aportan valor. Registra reversión e incertidumbre.
